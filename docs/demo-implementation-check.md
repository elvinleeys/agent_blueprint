# 구현 검사 화면 시연 방법

구현 검사 탭의 버튼(**같은 것으로 짝짓기 · 수정 요청에 포함 · 무시**)을 화면에서 직접 눌러 볼 수 있게 만든 시연 세트입니다.
구현 검사는 프로젝트에 저장된 설계도와 올린 코드를 비교하므로, ① 예시 설계도가 든 프로젝트가 필요하고 ② 그 설계도에 맞춘 완성 코드 폴더가 필요합니다.
둘 다 이 저장소에 들어 있습니다. 시험 데이터(`fixtures/implementation-check`)에서 만든 것이라 결과는 테스트(`core/impl-check/demo.test.ts`)로 고정되어 있습니다.

## 1. 예시 설계도가 든 프로젝트 만들기 (한 번만)

1. 로그인한 뒤 **새 프로젝트**를 만듭니다. 이름은 마음대로, 스택은 **Next.js · Tailwind CSS · FSD**로 고릅니다(예시 설계도의 스택과 같게).
2. 만든 프로젝트를 열고 주소창의 `/projects/<프로젝트 id>` 에서 **프로젝트 id**(`3f2b8c1e-…` 같은 uuid)를 복사합니다.
3. 터미널에서 아래를 실행해 SQL을 만듭니다. (DB에 접속하지 않고 SQL 글자만 출력합니다.)
   ```
   npm run demo:sql -- <프로젝트 id>
   ```
4. 출력된 SQL 전체를 Supabase 대시보드 → **SQL Editor** → New query에 붙여넣고 **Run**합니다(`docs/db-migration.md`와 같은 방식).
5. 프로젝트의 **구조 설계** 탭을 새로고침하면 "상품 상세" 설계도(노드 8개: ProductDetailPage, ProductGallery, ProductInfo, PriceTag, OptionSelector, AddToCartButton, useCart, ReviewSummary)가 보입니다.

설계도는 `fixtures/implementation-check/next/blueprint.json`(`core/schema/sample-blueprint.json` 기반 상품 상세)입니다. 지시서를 한 번도 내보내지 않았으므로 구현 검사의 기준은 "내보낸 기록이 없어 최신 판 1"입니다. **지시서** 탭에서 지시서를 내보내면 "지시서를 내보낸 판 1 기준"으로 바뀌는 것도 확인할 수 있습니다.

## 2. 올릴 코드 폴더 3개

`fixtures/demo-implementation-check/` 아래의 폴더를 **폴더 선택**으로 그대로 올립니다(파일 12개, `tsconfig.json` 포함이라 "설정 파일 1개 읽음"이 보입니다).

| 폴더 | 무엇인가 | 기대 결과 |
| --- | --- | --- |
| `correct` | 설계도대로 바르게 구현한 코드 | 카드 없음 · 설계 항목 65개 중 일치 65개 · 불일치 0개 · 확인 필요 0개 |
| `renamed` | 이름만 바꾼 코드(ProductGallery → **ItemImages**, 상태 cartCount → **count**, props discountRate → **discount**) | 확인 필요 카드 3장: 짝 확인 필요(ProductGallery ↔ ItemImages), 상태(useCart), props(PriceTag). 설계 항목 65개 중 일치 56개 · 불일치 0개 · 확인 필요 9개(카드 한 장이 항목 여러 개에 걸리므로 항목 수와 카드 수는 다릅니다). **[같은 것으로 짝짓기]가 보입니다** |
| `warning` | 경고가 나오는 코드 | 확실한 카드 3장(모두 경고): IC-03(AddToCartButton이 `features/add-to-cart/ui`가 아닌 `shared/ui`에 있음), IC-11(PriceTag 맨 바깥 요소에 margin), IC-12(ProductGallery 인라인 style). 설계 항목 65개 중 일치 64개 · 불일치 1개 · 확인 필요 0개, 금지 규칙 위반 2개 |

## 3. 버튼 확인 순서

1. **구현 검사** 탭 → `correct` 폴더 선택 → **검사하기**. 카드가 없고 집계가 65/65인지, "설정 파일 1개 읽음 / 못 따라간 설정 0개"가 보이는지 봅니다. 결과가 길면 스크롤을 내려도 맨 위의 "설계 항목 N개 중 일치 M개 · …" 집계 줄이 고정되어 따라오는지 봅니다(카드가 많은 `renamed`·`warning`에서 더 잘 보입니다).
2. 파일 목록을 **모두 지우기**로 비우고 `renamed` 폴더를 선택해 **검사하기**(또는 목록을 지우지 않고 다른 폴더를 올려도 됩니다. 같은 경로가 없어 합쳐지지 않으니 먼저 지우는 것이 깔끔합니다).
3. **확인 필요 카드 3장**이 나옵니다. 짝 확인 필요 카드의 후보 `ItemImages`(경로가 함께 보임)에서 **[같은 것으로 짝짓기]**를 누릅니다. 다시 검사한 결과에서 ProductGallery가 확실한 짝이 되어 그 카드가 사라지고 확인 필요 수가 줄어듭니다. "확정한 짝 1개"와 **[확정 취소]**가 보입니다.
4. 남은 확인 필요 카드(상태·props)에서 **[수정 요청에 포함]**을 누르면 아래 **수정 지시서**의 "확인 뒤 수정"에 그 항목이 들어가고, **[무시]**를 누르면 카드가 접히고 지시서에서 빠집니다. 둘 다 위쪽 "설계 항목 N개 중 일치 M개 · 불일치 · 확인 필요 K개" 집계는 바뀌지 않습니다.
5. 다시 **검사하기**를 눌러도 같은 카드의 포함·무시 선택이 유지되는지 봅니다.
6. 파일 목록을 비우고 `warning` 폴더로 검사합니다. 확실한 카드 3장과 수정 지시서의 "확실한 수정" 3개를 봅니다.
7. 다른 탭(구조 설계 등)에 갔다가 돌아와도 올린 파일·결과·선택이 그대로인지 봅니다.

## 시연 폴더를 다시 만들려면

시연 폴더는 시험 데이터에서 만든 것입니다. 시험 데이터가 바뀌면 아래로 다시 만듭니다(테스트가 폴더와 시험 데이터가 어긋나면 실패해서 알려 줍니다).

```
npm run demo:build
```

## 주의

- 시연 코드와 결과는 저장되지 않습니다. 새로고침하면 사라집니다.
- 예시 설계도 SQL은 프로젝트마다 한 번만 실행하세요(실행할 때마다 새 판이 하나씩 더해집니다).
- 이 SQL은 시연용 개발 도구입니다. 앱 화면에서 설계도를 가져오는 기능은 아직 없습니다.
