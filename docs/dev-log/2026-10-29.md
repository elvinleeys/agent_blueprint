| 서버가 `stack`·`source`·`generatedBy`·`version`을 요청값으로 덮어씀 | 모델이 바꾸거나 틀리는 일을 막기 위해 |
| OpenAI SDK 자동 재시도 끔(`maxRetries: 0`), 재시도는 스키마 검증 실패 1회뿐 | 429·5xx는 클라이언트의 재시도 버튼에 맡김(CLAUDE.md 에러 처리 규칙) |
| 재시도 조건 `남은 시간 ≥ max(첫 시도 시간, 15초)` | 재시도도 첫 시도와 비슷하게 걸리므로 |
| `maxDuration = 70` | 앱 내부 마감(45·60초)이 먼저 와서 우리 형식의 504를 내게 함 |
| 자동 보정(재시도 전): grid의 `direction`, flex의 `columns` 제거, 같은 부모 아래 `order` 중복 재정렬 | 기계적으로 고칠 수 있는 오류는 재시도(시간·비용) 없이 처리. FSD 위치 형식·이름·루트 개수 같은 의미 판단 오류는 보정하지 않음 |
| 보정 후 `direction`만 있던 grid responsive 항목은 삭제하고 "의도 확인 필요" 표시 | `columns: 1`로 바꾸는 추측은 하지 않기로 함 |
- 응답 `meta.normalized`에 보정 내역을 담고, 서버 로그에는 개수만 남긴다.
- 실측: 프롬프트 v2 text 30.0초(terra, `95ea8e8` 기록). 이후 사용자가 실제 환경(콘솔)에서 받은 응답은 14.7초, 시도 1회, 보정 0건.

| 결정 | 이유 |

| 표 4개: `projects`(이름·스택), `spec_inputs`(7개 항목 + `image_count`), `blueprints`, `prompt_exports`. 이미지·코드 원본 열 없음 | CLAUDE.md "원본은 분석 후 저장하지 않는다" |

| 과거 판 수정 거부(트리거, 오류 `BP001`) | 지시서가 출처 판과 연결되므로 과거 판이 바뀌면 연결의 의미가 사라짐 |

| 프로젝트·사용자 삭제 시 연쇄 삭제(회원 탈퇴 시 즉시 삭제) | 탈퇴 정책. `projects.user_id`가 `auth.users`에 `on delete cascade` |
| `prompt_exports`의 `(blueprint_id, project_id)` 복합 FK는 `on delete cascade` | `no action`이면 프로젝트 연쇄 삭제 때 설계도가 지시서보다 먼저 지워져 실패할 수 있음. 직접 삭제 거부는 트리거가 맡음 |
| RLS는 `authenticated`에만, `anon`은 REVOKE. 하위 표는 부모 프로젝트 소유로 확인(`with check` 포함) | 남의 프로젝트 id로 하위 행을 만들거나 옮기는 것을 막음 |
| `GRANT`를 명시하고 먼저 `revoke`. | Supabase가 새 표를 Data API에 자동 노출하지 않도록 기본값을 바꿈(공지상 기존 프로젝트는 2026-10-30부터). 이 프로젝트는 첫 사용자 생성이 10-29 10:35 UTC라 10-30 이전에 만들어졌고 옛 기본값(자동 부여)일 가능성이 높음 |
- 적용은 사용자가 대시보드 SQL 편집기로 직접 했고(저는 DB에 접근하지 않음), 격리 확인 스크립트가 오류 없이 끝났다(사용자 보고). 스크립트는 사용자 A·B 격리, 과거 판 수정·삭제 규칙, 프로젝트·사용자 삭제 시 연쇄 삭제, anon 거부를 검사한다.
- 저장소의 마이그레이션 파일은 `5725a50` 이후 변경이 없다. 적용된 SQL과 바이트 단위로 같은지는 DB에 접근할 수 없어 확인하지 못했고, 격리 스크립트 통과를 간접 증거로 보았다.
- 새 표를 만들 때는 같은 방식(RLS + 명시적 revoke/grant)을 따라야 한다(옛 기본값이면 새 표에 `anon` 권한이 자동으로 붙는다).

## 발생한 문제와 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| `/api/draft` 라우트를 작성하지 못함 | `.claude/settings.json`의 `Edit(app/**)`·`Edit(components/**)` 거부 규칙(스펙의 Open Question 1로 올림) | 사용자가 규칙을 삭제하고 세션 재시작(`1f2b7f6`). 이후 `app/` 수정 가능 확인 후 라우트 작성 |

## 남은 개선점

1. **(우선) 남의·없는 프로젝트의 설계도 불러오기와 판 목록도 404로 통일**
   - 현재 `GET /api/projects/[id]/blueprint`는 200 `{ blueprint: null }`, `GET .../revisions`는 200 `{ revisions: [] }`로 응답한다. RLS가 남의 행을 숨기므로 "없는 프로젝트"와 "판이 없는 내 새 프로젝트"를 구분하지 못한다. `PUT`·`POST`·`/api/draft`는 이미 404다.
   - 방향: 두 `GET` 핸들러가 `getProject`로 소유를 먼저 확인해 없거나 남의 프로젝트면 404(`not_found`)를 돌려준다. "판이 없는 새 프로젝트"만 200 `{ blueprint: null }`로 남긴다. `lib/api` 핸들러 테스트와 `docs/projects-api.md`·`SPEC-projects-api.md`의 표기도 함께 고친다.
2. 낙관적 동시성 제어 없음: 같은 프로젝트를 두 탭에서 저장하면 마지막 저장이 이긴다(편집기에서 저장 직렬화로 시작 가능).
3. 구조 검사 규칙(`core/rules`) 미구현: R-01~R-07, NX-01~NX-04, AR-01~AR-03 등. NX-03·NX-04·R-07은 `data-model.md`에 정의됨.
4. 화면 미구현: `/projects`는 임시 페이지, 로그인·계정은 디자인 없는 최소 마크업. 작업공간(트리 캔버스, 편집 패널), 지시서 내보내기, 판 목록 화면 없음.
5. `/api/explain`, `/api/analyze`는 501 스텁.
6. `spec_inputs`·`prompt_exports` 표는 있으나 저장 함수는 없음(해당 화면을 만들 때 추가하기로 함).
7. 클라이언트 이미지 축소(합계 4MB 이하) 미구현. 서버는 4MB 초과를 413으로 거절한다.
8. 사용자별 호출 제한(429)·사용량 집계 없음(요청 범위 밖으로 제외).
9. 확인하지 못한 것: Proxy가 모든 요청에서 `getClaims()`를 호출하는 비용(프로젝트의 JWT 서명 키가 비대칭인지 대칭인지 확인 못 함), Vercel Fluid compute 설정, 적용한 SQL과 저장소 파일의 바이트 단위 일치, 프로젝트 정확한 생성일.
10. 정리 후보: `lib/api`가 `lib/ai/draft-http.ts`의 `httpError`·`HttpError`를 가져다 쓴다(공용 위치로 옮기기), `supabase/config.toml`·`supabase/.gitignore`는 CLI `init`으로 생긴 파일이라 커밋하지 않았고 쓰지 않으면 삭제 가능.
