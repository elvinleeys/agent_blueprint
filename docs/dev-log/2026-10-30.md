| 결정 | 이유 |
| --- | --- |
| 시작 전 오류(401·400·413·404·503)는 상태 코드 + JSON, 통과하면 200 NDJSON 스트림(`stage`·`ping`·`done`·`error`) | 클라이언트가 `Content-Type`으로 구분. 스트림이 시작된 뒤에는 HTTP 상태를 바꿀 수 없음 |
| 서버는 10초마다 `{"type":"ping"}`. 종료·오류·예외·연결 끊김 모두에서 타이머 정리(테스트) | 사용자 승인. 단계 알림이 15~30초 비는 구간의 연결 유지 |

| 저장 실패는 `error`(503 `db_unavailable`)에 `blueprint`를 함께 담음. 이전의 "200 + `meta.saveError`" 폐지 | 이미 AI 비용이 든 초안을 버리지 않으면서 오류로 알림 |
| 클라이언트가 연결을 끊어도 서버는 생성과 저장을 끝까지 마침 | 비용이 든 초안을 잃지 않음 |

### 7-4. 입력·진행·오류
- 이미지: 고르는 순간 형식(PNG·JPEG·WebP)·5MB·3장을 검사하고, 전송 때 브라우저에서 가로 1,200px 이하·합계 4MB 이하로 줄인다(`core/image/fit-size.ts` 순수 함수 테스트, `lib/client/resize-images.ts` 캔버스). EXIF 회전 반영, PNG 투명은 흰 배경. **캔버스 축소는 자동 테스트가 없고 실제 큰 이미지 3장으로 확인한 결과를 아직 받지 못했다(확인 못 함).**
- `lib/client/draft-stream.ts`: 줄 이어 붙이기, `ping` 무시, 30초 무수신·종료 이상 감지, 전체 제한 텍스트 50초·이미지 65초(서버 마감 45·60초보다 길게), 중단 때 읽기 리더도 취소. `lib/client/run-draft.ts`: 축소 → 요청 → 스트림 → 설계도 재검증 → 화면용 오류(상태 코드·`fields`·다시 시도 여부·401 로그인 안내) 변환. 어떤 오류든 입력은 그대로.
- 스토어(`store/structure-store.ts`)는 작업공간마다 독립. 입력·진행 단계·오류·저장 안 됨 표시·선택·보기 상태를 가진다. 진행 중 중복 시작은 무시.
- 입력 문구: 이미지만 넣으면 "이미지만으로도 생성할 수 있어요…"(권장 안내, 막지 않음), 버튼 아래에 최소 조건 "7개 항목 중 하나 이상, 또는 이미지 1장 이상이면 생성할 수 있어요"를 상시 표시, 항목 이름에는 "(선택)"을 붙이지 않음(사용자가 두 번에 걸쳐 조정). 버튼은 설계도가 없으면 "초안 생성", 있으면 "초안 다시 생성"과 "새 판으로 추가되며 기존 초안은 보존됩니다". 기본 파일 입력은 숨기고 "이미지 추가" 버튼과 "N장 선택됨 · 최대 3장" 상태 문구를 보여 준다(키보드로 열 수 있음). 문구·버튼 이름은 `spec-form-text.ts`에 모아 테스트한다.

## 8. 노드 편집 (E1~E10)

오른쪽 정보 패널을 편집 패널로 바꿔 노드 내용(이름·종류·책임·상태·props·이벤트·데이터 조회·렌더링 방식·파일 위치·배치·차지 칸·스타일)과 구조(부모 변경·순서·자식 추가·삭제)를 고치고, 편집 결과가 미리보기·트리에 바로 반영되며 자동 저장되게 했다. 스펙·계획과 실제 구현이 달라진 점·알려진 한계는 `tasks/plan-node-edit.md` 17·18절에 있다. 아래 단계 이름은 처음 계획(E1~E10)과 같고, 화면 구역은 E6 한 번에 만들어 구조 편집(E7)과 합쳐졌다.

### 구조와 결정 (이유)
- **편집 연산은 `core/edit`의 순수 함수**(성공 시 새 설계도, 실패 시 거부 이유·노드·경로): 나중에 드래그 편집을 붙여도 같은 연산을 쓰게 하고, 규칙을 단위 테스트로 고정하려는 요구. 연산은 결과 전체를 `BlueprintSchema`로 검증해 통과한 것만 반영하므로 저장되는 설계도는 항상 유효하다. 값이 그대로면 설계도도 `generatedBy`도 바꾸지 않아 저장이 예약되지 않는다.
- **스키마에 `placement.span ≤ 부모 열 수` 추가**(`5d644ba`, 별도 커밋): 처음에는 편집 연산이 검사하는 안이었으나 "초안·저장·편집이 같은 규칙을 쓰게" 스키마로 올렸다. 추가 전에 저장된 설계도를 점검하는 SQL을 사용자가 실행해 0건임을 확인했고, 자동 보정에 "span을 열 수로 줄이기"를 넣었다(`3e2a478`).
- **자식을 받는 노드의 빈 배치는 세로 flex(간격 없음)로 채우고, client 조상 아래로 옮기거나 추가한 노드는 client로**(`d348d83`): 스키마가 "훅이 아닌 자식이 있으면 layout 필수"라 채우지 않으면 거부되고, client가 불러온 컴포넌트는 server일 수 없기 때문(NX-04). 채우거나 바꾼 사실은 결과(`filledLayout`·`toClient`)로 알려 화면이 안내한다.
- **훅↔컴포넌트 종류 전환과 루트가 아닌 노드의 페이지 지정은 거부**(`100e097`, `0deeb04`): 이름 형식·`layout`·`style`·`renderMode` 제약이 달라 자동 변환은 오류 위험이 크다고 판단, "새 노드로 추가하세요"로 안내. 페이지는 화면 단위 최상위라 루트만(스키마는 그대로, AI 초안의 같은 문제는 검사 규칙에서 다룬다).
- **사용자가 고친 필드는 `assumedFields`에서 빼고, 목록이 비면 `assumed=false`**: "AI 가정"은 사용자가 확인할 대상이라는 뜻이라 직접 고친 값에는 남기지 않는다(`isAssumedField`가 패널의 표시와 해제 판정을 함께 쓴다).
- **글자마다 연산을 적용하고 거부되면 칸에만 남김**: 틀린 값은 설계도에 반영·저장하지 않고 칸 옆에 이유를 보인다. 200개 노드에서 `updateNode` 1회 중앙값 0.35ms(검증 포함)라 글자마다 실행해도 부담이 없다고 측정(`tasks/plan-node-edit.md` 12·15절).
- **트리 재배치(dagre)는 구조가 바뀔 때만**(`d3cbeb0`): 이름·스타일 같은 내용 수정에는 다시 계산하지 않는다(카드가 고정 크기). 200개 노드에서 dagre 전체 재계산은 중앙값 26.6ms라 글자마다 돌리면 안 되는 비용이었다.
- **자동 저장은 저장 큐를 거친다**(`aa42d3a`): 800ms 디바운스, 한 번에 하나씩, 전송 중 편집은 합쳐 최신본만. 초안을 다시 생성할 때는 ① 편집 막기 → ② `settle`(진행 중 저장 대기, 보내지 않은 저장 취소) → ③ 생성 순서를 고정(`generateDraft`, `3840e3f`). 새 AI 초안 위에 이전 편집이 저장되면 안 되기 때문. 이 순서를 실제 스토어·큐로 테스트하고, 순서를 지우는 변이로 테스트가 실패하는 것을 확인했다.
- **떠나기 전 경고**(`df21040`): 탭 닫기·새로고침은 `beforeunload`, 링크는 `GuardedLink`(Next `onNavigate`), 로그아웃은 클릭 처리 안에서 확인, 경고는 `window.confirm`. 브라우저 뒤로·앞으로는 막을 공식 방법이 없어 구현하지 않았다.
- **다시 생성 확인 조건**(`26a926a`): 저장되지 않은 수정이 있을 때, 그리고 최신 판이 사용자가 고친 설계도(`generatedBy: "user"`)일 때(저장이 끝났어도, 이전 판으로 밀려나므로). 최신 판이 AI 초안이고 저장되지 않은 수정도 없으면 확인 없이 생성. 조건은 `regenerateReasons`로 분리해 테스트로 고정.
